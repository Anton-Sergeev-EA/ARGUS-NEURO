# ARGUS-NEURO

**Диагностика силовой электроники с объяснением результатов, проверкой качества данных и явной неопределённостью.**

[English](README.md) · [Контракт диагностики](docs/RELIABILITY.md)

Проект работает как исследовательский прототип на синтетических данных морских преобразователей и энергоблоков БПЛА. Промышленная надёжность и ресурс реального оборудования пока не подтверждены испытаниями.

## Собственное направление развития

1. **Паспорт диагноза:** идентификатор результата, отпечаток набора моделей, отклонения датчиков и расхождение детекторов. Можно установить, какой набор моделей сформировал результат. Это не цифровая подпись и не доказательство причины отказа.
2. **Право системы отказаться от прогноза:** отсутствие истории, пропуски времени, некорректные измерения и несовместимые модели явно отражаются в ответе. Неизвестное состояние не считается исправным.
3. **Контроль нестабильности датчиков:** независимый канал оценивает среднеквадратичное отклонение окна от исправных обучающих данных отдельно для класса оборудования. Знакопеременная нестабильность не исчезает при усреднении.
4. **Честная работа при потере связи:** данные помечаются устаревшими, соединение восстанавливается; искусственная демонстрация запускается только по кнопке и явно обозначена.

Это реализованные особенности ARGUS-NEURO; мировая уникальность и преимущество над другими продуктами не заявляются без сравнительных испытаний.

## Запуск

Проверенное окружение: Linux, Python 3.12, GCC 13, CMake 3.28. Node 22 нужен только для тестов интерфейса.

```bash
bash scripts/setup_env.sh
bash scripts/train_all.sh
bash scripts/run_dashboard.sh
```

Откройте `http://127.0.0.1:8000`. Установка создаёт `.venv`; версии основных Python-зависимостей закреплены.

Обучение сохраняет каждый запуск в отдельный `artifacts/run-*`. После экспорта, проверки совпадения ONNX/PyTorch и проверки загрузки обновляется указатель `artifacts/active.json`. Предыдущие веса сохраняются. При ошибке указатель не переключается. Для загрузки нового набора перезапустите сервер.

Старые демонстрационные веса в корне `artifacts/` не содержат обязательных метаданных нового формата: после обновления нужно выполнить обучение. Если модели недоступны, приложение показывает ограниченный режим и не выдумывает прогноз ресурса.

Переменная `ARGUS_ARTIFACTS_DIR` позволяет выбрать доверенный локальный набор моделей, `ARGUS_PORT` — порт, `ARGUS_HOST` — адрес. По умолчанию сервер доступен только локально. Приём телеметрии реального оборудования, авторизация и постоянное хранилище ещё не реализованы.

## Что означают результаты

- `warming_up`: накапливаются 24 последовательных измерения с шагом обучения, по умолчанию 5 секунд. Спектральная тревога уже возможна; прогноз тренда и ресурса отсутствует.
- `ready`: входы пригодны и полный набор диагностики выполнен. Это не сертификат точности на реальном оборудовании.
- `invalid_data`: измерения или временная последовательность некорректны.
- `degraded`: модели или часть опорных данных недоступны.

`is_anomaly=null` означает неизвестный результат. Индекс здоровья — эвристический индикатор, не вероятность отказа. Отклонения датчиков показывают наблюдаемое отличие от эталона, не устанавливают причину неисправности.

Ресурс показывается в процентах синтетического горизонта. В API часы рассчитываются только для симуляции из её временной шкалы. Условные 240 часов убраны. Для иных источников часы не выдаются. Интервал по ошибкам валидации не гарантирует покрытие на реальном оборудовании.

## Проверки

```bash
bash scripts/build_cpp_core.sh
ctest --test-dir build --output-on-failure
PYTHONPATH="$PWD/python:$PWD/build/cpp_core" OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 .venv/bin/python -m pytest python/tests -q
PYTHONPATH="$PWD/python" OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 .venv/bin/python -m pytest python/tests -q
.venv/bin/ruff check python
.venv/bin/ruff format --check python
node --test web/dashboard/tests/*.test.cjs
```

Разделение обучения, валидации и теста выполняется по целым траекториям до создания пересекающихся окон. Нормализаторы моделей раздельные. Отчёты содержат seed, состав разбиений, версии, контрольные суммы и сравнение RUL с медианным прогнозом.

ONNX проверяется структурно и численно через ReferenceEvaluator на трёх масштабах входа. Реализация инференса ONNX Runtime на C++ остаётся следующим этапом.

Результаты эксперимента: [experiments/LOG.md](experiments/LOG.md). Детали реализации и ограничения: [docs/RELIABILITY.md](docs/RELIABILITY.md).
