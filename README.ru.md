# ARGUS-NEURO

**Платформа прогнозной диагностики и мониторинга состояния силовой электроники — для морских систем управления и энергосистем беспилотных летательных аппаратов в едином решении.**

## Почему одна платформа для двух отраслей

Судовой преобразователь частоты, управляющий рулевой машиной, и блок распределения питания беспилотного летательного аппарата, питающий полётный контроллер, на первый взгляд — совершенно разные устройства. Но электрически это один и тот же класс объектов: силовой электронный узел с телеметрией по напряжению, току, температуре, вибрации и частоте, который деградирует по ограниченному и хорошо изученному набору сценариев — перегрев, износ подшипников/изоляции, просадка напряжения, дрейф частоты — задолго до фактического отказа.

**ARGUS-NEURO** — единая платформа мониторинга состояния и прогнозного технического обслуживания, построенная на этом наблюдении. Вместо двух узкоспециализированных диагностических систем для двух отраслей — один универсальный конвейер: обработка сигналов, классическое машинное обучение, глубокое обучение и живой дашборд, — проверенный на синтетической, но физически обоснованной телеметрии как для морских преобразователей/приводов, так и для блоков питания БПЛА.

## Ключевые возможности

- **Двухуровневая детекция аномалий.** Быстрая классическая модель (Isolation Forest) в реальном времени проверяет мгновенный спектр сигнала на периферийном оборудовании; глубокая рекуррентная модель (LSTM-автоэнкодер) улавливает медленные многомерные тренды, проявляющиеся только со временем.
- **Оценка остаточного ресурса (RUL).** GRU-регрессор превращает скользящее окно телеметрии в практически применимое число «часов до обслуживания», а не просто бинарный сигнал тревоги.
- **Нативное ядро на C++20.** RMS, пик-фактор, эксцесс, асимметрия и собственная реализация радикс-2 БПФ для спектральных признаков — доступны из Python через `pybind11`, с резервной реализацией на чистом NumPy, если C++ toolchain недоступен.
- **Экспорт в ONNX.** Обе глубокие модели экспортируются в ONNX для инференса на C++ (ONNX Runtime) прямо на периферийном оборудовании, где работает нативное ядро извлечения признаков — без Python-интерпретатора в эксплуатационном контуре.
- **Живая веб-консоль.** Дашборд на чистом HTML/CSS/JS без внешних зависимостей транслирует состояние флота через WebSocket в реальном времени, с офлайн-режимом демонстрации на стороне клиента.
- **Двуязычность, воспроизводимость, тесты.** Каждая модель обучается на синтетическом, но реалистичном симуляторе (конвейер полностью работоспособен без закрытых данных), покрыта модульными тестами и подключена к CI.

## Двухуровневая архитектура ML/DL

Каскад — это осознанное архитектурное решение, а не две модели, соединённые «для галочки»:

| Уровень | Модель | Вход | Почему именно так |
|---|---|---|---|
| 1 | `SpectralBaselineDetector` (Isolation Forest, scikit-learn) | 11-мерный вектор признаков из одного окна сырого сигнала (через `argus_core`) | Достаточно дёшев, чтобы работать непрерывно на ограниченном периферийном оборудовании; не требует истории; мгновенно ловит резкие, спектрально очевидные неисправности. |
| 2a | `LSTMAutoencoder` (PyTorch) | Скользящее окно 6-канальной телеметрии, обучается без учителя только на исправных данных | Учится тому, как выглядит *нормальное* многомерное поведение во времени — улавливает медленный дрейф, незаметный в единичном замере, без необходимости в размеченных отказах (которых у реальных флотов почти нет). |
| 2b | `RULRegressorGRU` (PyTorch) | То же скользящее окно, обучается на размеченных траекториях деградации из симулятора | Превращает «что-то не так» в «сколько времени до обслуживания» — именно то число, от которого зависит решение о планировании ремонта. |

`HealthInferenceEngine` (`python/argus/inference/engine.py`) объединяет все три оценки в единый индекс здоровья 0–100. Если обученные артефакты не найдены, система прозрачно переключается на эвристику, оставаясь работоспособной ещё до первого запуска обучения.

│   ├── argus/

│   │   ├── export/          # экспорт в ONNX
│   │   ├── inference/       # HealthInferenceEngine (слияние оценок в рантайме)
│   │   └── api/              # backend FastAPI + WebSocket
│   ├── tests/                # набор тестов pytest

## Технологический стек

| Слой | Технологии |
|---|---|
| Нативное ядро | C++20 (concepts, `<span>`, `constexpr`), CMake, pybind11 |
| ML / DL | Python 3.11, PyTorch (LSTM / GRU), scikit-learn (Isolation Forest), ONNX / `torch.onnx` (dynamo-экспортёр) |
| Backend | FastAPI, WebSockets, Uvicorn (asyncio) |
| Frontend | Чистые HTML5 / CSS3 / JavaScript (индикаторы и спарклайны на Canvas, без внешних CDN) |
| Тестирование / CI | pytest, нативные тесты на assert без зависимостей, GitHub Actions |

## Быстрый старт

```bash
git clone <адрес-репозитория> argus-neuro && cd argus-neuro

# 1. Установить зависимости Python и собрать нативное ядро C++ (создаст ./build)
bash scripts/setup_env.sh

# 2. Указать Python путь к пакету и скомпилированному расширению
export PYTHONPATH="$PWD/python:$PWD/build/cpp_core"

# 3. (Опционально) переобучить все модели с нуля — предобученные
#    демонстрационные веса уже включены в ./artifacts
bash scripts/train_all.sh

# 4. Запустить тесты
cd python && python -m pytest -v && cd ..

# 5. Запустить живой дашборд
bash scripts/run_dashboard.sh
# -> открыть http://localhost:8000/
```

Дашборд работает и при прямом открытии `web/dashboard/index.html` без backend'а: при отсутствии WebSocket-соединения он автоматически переключается на автономную демонстрационную симуляцию на стороне клиента.

## Тестирование

- `cpp_core/tests/test_signal_features.cpp` — тесты на assert без внешних зависимостей: RMS/среднее для известных сигналов, определение доминирующей частоты через БПФ на синтетической синусоиде, проверки спектральной энергии.
- `python/tests/` — проверки симулятора, корректность извлечения признаков (сверка с известной синусоидой), формы прямого прохода моделей, тест на снижение функции потерь при обучении, разделение нормальных и экстремальных данных Isolation Forest.
- `.github/workflows/ci.yml` собирает нативное ядро, запускает его тесты, затем весь набор pytest против скомпилированного расширения.
