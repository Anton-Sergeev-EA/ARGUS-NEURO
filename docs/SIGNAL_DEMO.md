# Почему основной частоты недостаточно: пример на C++ и Python

Что произойдёт, если к сигналу 50 Гц добавить компоненту 250 Гц, которая слабее основной? Основная частота может остаться прежней, хотя форма сигнала и его энергия изменились. Это удобный небольшой пример того, зачем диагностике несколько признаков.

В ARGUS-NEURO один контракт признаков реализован на C++20 и NumPy. Этот пример запускается без моделей, сервера и обучения. Он иллюстрирует обработку синтетической формы сигнала; автоматическую классификацию неисправностей здесь мы не выполняем.

![Сравнение RMS, спектральной энергии и основной частоты](assets/signal-demo.png)

## Быстрый запуск

Из корня репозитория, на Python 3.12 в отдельном окружении:

```bash
python3 -m venv .venv-demo
.venv-demo/bin/python -m pip install numpy==2.5.3
PYTHONPATH="$PWD/python" .venv-demo/bin/python -m argus.demo_signal --output /tmp/argus-signal-numpy.json
```

На Windows используйте `.venv-demo\Scripts\python.exe` и задайте `PYTHONPATH` средствами своей оболочки. Если файл результата уже существует, выберите новое имя: демонстрация не перезаписывает прошлые результаты.

Для нативного пути в уже установленном окружении проекта:

```bash
bash scripts/build_cpp_core.sh
PYTHONPATH="$PWD/python:$PWD/build/cpp_core" .venv/bin/python -m argus.demo_signal --output /tmp/argus-signal-native.json
```

Для первой полной установки см. [README](../README.md#первая-установка-на-ubuntu). В JSON проверьте `backend`: `numpy` или `native_cpp`. Если расширение не найдено, используется NumPy. При каждом запуске выбранный путь сравнивается с эталонной NumPy-реализацией с допусками `rtol=atol=1e-10`; расхождение завершает выполнение ошибкой. На NumPy-пути это проверка воспроизводимого вычисления, а не сравнение двух разных реализаций.

## Сигнал и результат

Окно содержит 2 048 отсчётов при 2 048 Гц. Исходный сигнал — синус 50 Гц с амплитудой 1 и гауссовским шумом со стандартным отклонением 0,02. Генератор — NumPy `default_rng(42)`. Второе окно использует **тот же шум** и дополнительный синус 250 Гц с амплитудой 0,8. Единицы амплитуды условные.

| Признак | Исходный сигнал | Добавлена компонента 250 Гц |
|---|---:|---:|
| RMS | 0,706771 | 0,905892 |
| Спектральная энергия без DC | 0,249762 | 0,410320 |
| Основная частота, Гц | 50 | 50 |

Это результаты локального запуска с Python 3.12.3, NumPy 2.5.3 и нативным расширением. RMS вырос примерно на 28 %, спектральная энергия — на 64 %. Основная частота не изменилась: компонента 50 Гц осталась сильнее добавленной. Один этот признак пропустил бы изменение.

Почему здесь нет порога тревоги? Два специально построенных окна не дают ни статистики ложных тревог, ни основания выбрать рабочий порог. На реальных данных RMS может меняться вместе с нагрузкой и режимом работы. Для детектора нужны независимые данные исправных режимов, калибровка и отдельный тест.

## Контракт важнее названия языка

В обеих реализациях используется один порядок 11 признаков. БПФ дополняет окно нулями до степени двойки, нормирует спектр на дополненную длину и исключает DC из спектральных признаков. Оконная функция не применяется. Смена реализации не должна незаметно менять входы обученной модели.

Демонстрация не измеряет ускорение. Сравнение C++ и NumPy по времени требует отдельного протокола: одинаковых входов, прогрева, повторов и описания машины. Совпадение чисел само по себе не доказывает ускорения.

## От формы сигнала к ML-диагностике

Полный проект объединяет спектральный детектор, LSTM-автоэнкодер, исправные эталоны датчиков и GRU для синтетической оценки ресурса. В [сохранённом эксперименте](../experiments/2026-09-30_reliability/notes.md) автоэнкодер получил F1 0,669 и recall 0,585 на независимом синтетическом тесте. Это исторические результаты отдельного эксперимента, а не метрики двух окон выше.

Для оценки модели целые траектории разделяются до построения окон. Иначе соседние перекрывающиеся окна могут попасть и в обучение, и в тест. Подробнее: [контракт диагностики](RELIABILITY.md).

Следующий полезный вклад — воспроизводимый пример, где C++ и NumPy расходятся, или проверка модели на разрешённых к публикации измерениях с описанными режимами работы. Если нашли такой случай, приложите минимальный вход и команду воспроизведения в issue.

## Построить график из своего JSON

Необязательная зависимость — Matplotlib 3.6 или новее:

```bash
python3 -m pip install matplotlib
python3 scripts/plot_signal_demo.py /tmp/argus-signal-native.json /tmp/argus-signal.png
```

Сохранённая иллюстрация построена Matplotlib 3.6.3. График читает готовый JSON и не пересчитывает признаки. Скрипт отказывается заменять существующий выходной файл.
