# Эксплуатация ARGUS-NEURO (боевой стек)

Что сделано для развёртывания, что проверено и где границы. Развёртывание описано для Linux x86-64 с Docker Compose v2: на нём всё проверено.

## 1. Для чего это можно и нельзя использовать

| Можно | Нельзя без собственной валидации |
|---|---|
| Оценка остатка ёмкости и интервала для лабораторных ячеек (NASA, CALB, HUST) | Решения об остановке, допуске или безопасности оборудования, транспорта, зарядных станций, БПЛА |
| Загрузка собственной истории ёмкости и просмотр отчёта | Эксплуатация пакетов EV, самокатов, пауэрбанков: проверки на них не было, интервал пакетов не калиброван |
| Сбор телеметрии OCPP 1.6J в архив (коллектор) | «Диагностика реальных станций»: модели оборудования обучены на синтетике, реальных отказов не видели |
| Пилот в закрытой сети с наблюдением специалиста | Самостоятельная работа без присмотра |

При смене химии или протокола покрытие интервала падало до 83 % (CALB) и 73 % (NASA) при заявленных 90 %, см. [BACKTEST.md](BACKTEST.md).

## 2. Что входит в боевой стек

`docker-compose.prod.yml`: приложение (без публикации порта) и прокси Caddy 2.11.7.

- **TLS.** Для домена Caddy сам получает сертификат Let's Encrypt (порты 80 и 443 должны быть доступны из интернета). `ARGUS_SITE=localhost` включает собственный тестовый центр сертификации.
- **Вход.** HTTP Basic на всё, кроме `/api/health` (открыт для балансировщика, данных не отдаёт) и `/api/ingest/*` (своя авторизация по токену `ARGUS_INGEST_TOKEN`).
- **Заголовки.** HSTS, `nosniff`, запрет вложения во фрейм, `no-referrer`; заголовок `Server` убран. Политики CSP нет: она не проверялась на панели.
- **Ограничения.** Тело запроса до 4 МБ; лимит 60 запросов в минуту на клиента для тяжёлых батарейных маршрутов; корректный IP клиента берётся из заголовков прокси.
- **Контейнеры.** Без root, корневая файловая система только для чтения, все привилегии сброшены, лимит 2 ГБ памяти и 2 ядра для приложения, автоперезапуск.
- **Журналы.** `json-file`, ротация 5 файлов по 10 МБ на сервис.

## 3. Развёртывание

```bash
cp .env.example .env            # заполните, .env не коммитится
docker run --rm caddy:2.11.7-alpine caddy hash-password --plaintext 'длинный-случайный-пароль'
# вставьте хеш в ARGUS_PASSWORD_HASH (символы $ в .env для Compose удвойте: $$)
docker compose -f docker-compose.prod.yml --env-file .env up -d --build
docker compose -f docker-compose.prod.yml --env-file .env exec argus bash scripts/train_all.sh
docker compose -f docker-compose.prod.yml --env-file .env restart argus
bash scripts/prod_smoke.sh https://ваш-домен operator 'пароль'
```

Без обучения моделей страница оборудования работает в базовом режиме и об этом сообщает; батарейная страница обучения не требует. Пароль минимум 16 случайных символов: у входа нет блокировки после неудачных попыток, поэтому ограничьте доступ сетью или VPN. Один общий пользователь, поимённого журнала действий нет.

Нестандартные порты (`ARGUS_HTTP_PORT`, `ARGUS_HTTPS_PORT`) годятся для проверки; перенаправление с HTTP ведёт на порт 443, поэтому для работы оставьте 80 и 443.

## 4. Мониторинг

- **Живость:** `GET /api/health` (200 или 503), открыт.
- **Метрики:** `GET /api/metrics` в формате Prometheus, за паролем: `argus_up`, `argus_model_backed`, `argus_connected_clients`, `argus_last_tick_age_seconds`, `argus_producer_error`.
- **Рекомендуемые оповещения:** `argus_up == 0` более минуты; `argus_last_tick_age_seconds > 10`; `argus_model_backed == 0` после обучения; `argus_producer_error == 1`.
- Метрик по запросам и задержкам в приложении нет; снимайте их с прокси или нагрузочным тестом.

## 5. Копии и восстановление

```bash
export ARGUS_COMPOSE="docker compose -f docker-compose.prod.yml --env-file .env"
bash scripts/backup_volume.sh            # backups/argus-data-<время>.tar.gz
bash scripts/restore_volume.sh backups/argus-data-....tar.gz
```

Копия содержит модели, скачанные открытые наборы и сохранённые отчёты. Скрипт проверяет, что архив читается, а восстановление отказывается от архивов с абсолютными путями и `..`. Проверено на живом стеке (создание, отказ от опасного архива, возврат содержимого). Расписание и хранение копий вне хоста настраивайте сами; ключи и `.env` в копию не входят.

## 6. Обновление и откат

1. Сделайте копию (раздел 5).
2. `git pull`, затем `docker compose -f docker-compose.prod.yml --env-file .env up -d --build`.
3. `scripts/prod_smoke.sh`.
4. Откат: `git checkout <прежний коммит>`, повторить шаг 2; при порче данных восстановить копию.

После обновления моделей обучите их заново: версии библиотек записаны в `python/requirements.txt`.

## 7. Что измерено (нагрузка)

Стенд: ноутбук i5-1235U, 23 ГБ ОЗУ, весь стек в Docker Desktop, запросы через прокси с TLS и паролем, 20 секунд, 24 параллельных запроса (по 8 на три маршрута) и 20 WebSocket-клиентов (`scripts/load_test.py`).

| Показатель | Значение |
|---|---|
| Запросов в секунду (сумма) | около 220, ошибок нет |
| Задержка p50 / p95 / p99 | около 70 / 320 / 570 мс при полной загрузке |
| WebSocket | 20 из 20 клиентов подключились и получали сообщения |
| Память приложения | около 258 МБ; прокси около 48 МБ |

Приложение работает одним процессом (состояние потока телеметрии общее), горизонтальное масштабирование не предусмотрено. Нагрузка выше этой, длительные прогоны и отказоустойчивость не проверялись.

## 8. Известные ограничения

- Один экземпляр, без репликации и без отказоустойчивости.
- Коллектор OCPP (`python -m argus.ingest.csms`) в боевой Compose не включён: он слушает `127.0.0.1`, а для станций снаружи нужны учётные данные и защищённый канал (`wss`); решите это отдельно, когда появится реальная станция.
- Проверено только на Linux x86-64. arm64, Windows и macOS не проверялись.
- Данные открытых наборов не входят в образ (лицензии); их скачивает пользователь.
- Уязвимости в зависимостях отслеживает Dependabot; автоматических проверок образа на уязвимости нет.
